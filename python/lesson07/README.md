# Lesson 07: Filtering, Sorting, and Pagination with PostgreSQL

## Learning objectives

By the end of this lesson, you should be able to:

- Extend a SQLAlchemy model and Pydantic schemas with a course field.
- Filter a database query using optional query parameters.
- Sort results consistently before paginating them.
- Use SQLAlchemy `offset()` and `limit()` to select a page of results.
- Seed a PostgreSQL table with a bulk `INSERT ... SELECT` statement.
- Verify filtering and pagination with Postman.

## Part 1: Extend the project model with a course

Filtering by course requires a `course` column in PostgreSQL and a corresponding attribute in the Python model and API schemas.

1. Copy the Lesson 05 project files into `python/lesson07/`, including the Alembic configuration, migration history, `db/`, `schemas/`, `server.py`, and `requirements.txt`.
2. In `db/models.py`, add a required string `course` column to the `Project` mapped class.
3. In `schemas/project.py`, include `course` in the shared project fields so create, update, and response schemas handle it. Ensure the status schema accepts the seed values used in this lesson: `TO DO`, `STARTED`, `DONE`, and `CANCELLED`.
4. Create and inspect a migration from the `python/lesson07/` folder:

   ```powershell
   alembic revision --autogenerate -m "add course to projects"
   alembic upgrade head
   ```

   Review the generated migration before applying it. If the table already contains projects, make sure the migration safely handles existing rows—for example, add the column as nullable, backfill it, and then make it non-null, or use an appropriate temporary server default. Do not drop the existing table or its data.
5. Configure this lesson's `DATABASE_URL` in its local `.env` file. Do not commit `.env` or database credentials.

The supplied SQL seed file expects the `projects` table to contain `name`, `due_date`, `course`, and `status`. The existing ID and timestamp columns should continue to be generated by the database.

## Part 3: Implement filtering, sorting, and pagination

Update the `GET /api/projects/` route in `server.py`. Keep the route's database session dependency and response model from the previous lesson.

1. Add optional `course` and `status` query parameters. Only add a filter when its parameter was supplied.
2. Add a `page` query parameter with a default of `1` and a minimum of `1`. Use a page size of `10`.
3. Apply filters before pagination. Sort by project name ascending, then by ID ascending to ensure a stable order when names match.
4. Calculate the offset as `(page - 1) * page_size`, then apply SQLAlchemy `offset()` and `limit()`.

The core query pattern is:

```python
query = db.query(Project)

if course is not None:
    query = query.filter(Project.course == course)
if status is not None:
    query = query.filter(Project.status == status)

projects = (
    query.order_by(Project.name.asc(), Project.id.asc())
    .offset((page - 1) * page_size)
    .limit(page_size)
    .all()
)
```

Declare and validate the FastAPI query parameters in the route signature (for example, use `Query(default=1, ge=1)` for `page`). Return the resulting list. An invalid page such as `page=0` should receive FastAPI's `422 Unprocessable Entity` response.

## Part 4: Test with Postman

Start the application from the `python/lesson07/` folder:

```powershell
.venv\Scripts\Activate.ps1
uvicorn server:app --reload --port 3000
```

Send `GET` requests to the following endpoint. The trailing slash is part of the route:

- `http://localhost:3000/api/projects/` — first 10 projects, sorted by name.
- `http://localhost:3000/api/projects/?status=STARTED` — only projects with that status.
- `http://localhost:3000/api/projects/?course=WebAPIs` — only projects for that course.
- `http://localhost:3000/api/projects/?status=STARTED&course=WebAPIs` — both filters applied.
- `http://localhost:3000/api/projects/?page=2` — the next page of 10 projects.
- `http://localhost:3000/api/projects/?page=100` — the final 10 seed projects when using an otherwise empty table.
- `http://localhost:3000/api/projects/?page=101` — an empty JSON array when using an otherwise empty table.
- `http://localhost:3000/api/projects/?page=0` — validation error (`422`).

Also combine filters with pagination, for example `http://localhost:3000/api/projects/?course=WebAPIs&status=STARTED&page=2`. Filters should apply to the full result set before the requested page is selected.
